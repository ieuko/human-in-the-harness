# piを初めて使う

このプロジェクト用の起動方法です。人間との接続を試す拡張と、日本語で応答するための指示を読み込みます。

## 起動する

macOSでは、プロジェクトのフォルダにある`Piを起動.command`をFinderでダブルクリックします。ターミナルが開き、ビルドしてからpiが起動します。

ターミナルで起動する場合は、プロジェクトのフォルダで実行します。

```sh
npm run pi
```

引数も渡せます。前回のセッションを続ける場合は次のようにします。

```sh
npm run pi -- --continue
```

pi本体の`pi`コマンドだけで起動した場合、この起動ファイルが指定する拡張や日本語の指示は自動では読み込まれません。

## モデルの接続先を選ぶ

認証が未設定なら、piの入力欄で`/login`を実行します。接続先を選び、画面に表示されるログインまたはAPIキーの入力手順に従います。接続先によって選べる方法は異なります。

APIキーはpiの画面で入力します。このチャットやプロジェクトのファイルへ貼る必要はありません。認証の情報はpiのユーザー設定で管理されます。

接続後は`/model`で使用するモデルを選びます。接続先を決めていなくても、`/human-context`などモデルを呼ばないコマンドで拡張の設定を確認できます。

## 最初の試行

まず`/human-context`を実行し、モデルへ渡す概念説明と参加者の説明を確認します。

その後、例えば次の文章を入力します。

> Human-in-the-Harnessの接続を試します。human_describeで接続を確認し、私にしか決められないことを一件、human_submitで依頼してください。受付後は回答を作らず、私の入力を待ってください。

依頼が作られたら`/human-pending`でIDと版を確認し、次の形式で回答します。

```text
/human-respond 依頼ID answer 1 "ここに自分の回答を書く"
/human-resume
```

`1`は確認した依頼の版に置き換えます。回答はJSONの文字列なので引用符で囲みます。依頼が構造化された回答を求めている場合は、その形式のJSONを指定します。

`/human-resume`が保存した入力をモデルへ渡し、続きを開始します。回答が遅れても依頼は保存されます。受理した結果の使い方は、現在の課題に従います。

## 終了・再開

`/quit`で終了します。もう一度`Piを起動.command`を開き、`/resume`で以前のセッションを選べます。ターミナルから`npm run pi -- --continue`でも再開できます。

モデルを動かすには接続先の認証が必要です。サービス契約や利用条件は、選んだ接続先の画面で確認してください。
