# piへの接続

pi 1.5.0に対する拡張を実装しています。実際のローダーとSDKを使って、依頼・回答・分岐とモデルへ渡す文脈を検証しています。プロバイダーは外部通信しないスクリプト化したものを使い、実モデルでの振る舞いはまだ評価していません。

## 起動

```sh
npm ci --ignore-scripts
npm run build
npx --no-install pi -e ./dist/src/adapters/pi.js
```

モデルの設定と認証は、利用するpiの設定に従います。Human-in-the-Harness自体はモデルの認証情報を管理しません。

保存先はpiの作業フォルダの`var/hith.sqlite`です。別のターミナルからCLIで回答する場合も、同じ保存先を指定します。`HITH_DATABASE`に絶対パスを指定すると、作業フォルダが違う場合も同じストアを利用できます。

## モデルに追加するツール

| ツール | 内容 |
|---|---|
| `human_describe` | 人間コンポーネントの概念・参加者・非同期の契約・依頼状態を確認する |
| `human_submit` | 任意の依頼を保存して受付IDを返す |
| `human_get` | 現在の実行に属する依頼の状態や結果を取得する |
| `human_amend` | 人間からの質問などを踏まえ、依頼の文脈や条件を更新して版を進める |
| `human_cancel` | 現在の実行に属する依頼を取り消す |

`human_submit`は、`prompt`に加えて`recipient`、`context`、`responseSchema`、`deadlineAt`を任意で受け取ります。宛先の既定値は設定された先頭の参加者で、未設定時は`human`です。人間が記憶、調査、計画、評価のどれを担うかを固定しません。

実行開始時には、概念と接続の契約をモデルへ説明します。現在の依頼状態と参加者の説明は文脈上のデータとして渡します。詳しくは[モデルへの情報開示](model-disclosure.md)を参照してください。

このツールの完了は受付の完了です。拡張は全体の処理を強制終了せず、回答に依存しない処理を続けることができます。モデルには、結果がない状態で`human_get`を繰り返して待機しないよう説明を加えます。ループを停止する方策を保証する仕組みではありません。

## 人間の操作

```text
/human-context
/human-pending
/human-respond 依頼ID question 1 "どの条件を優先しますか？"
/human-respond 依頼ID answer 1 "前回の決定理由も考慮してください。"
/human-resume
```

`/human-context`では、この拡張がモデルへ提供する説明・参加者・依頼状態を確認できます。

`/human-respond`の形式は「依頼ID、入力の種類、確認した版、JSON」です。構造化した回答も指定できます。版は依頼の表示から確認します。文字列の回答もJSONの文字列として引用符で囲みます。

CLIから回答することもできます。

```sh
node dist/src/cli.js respond '依頼ID' --revision 1 --text '回答' --database 'piと同じデータベースのパス'
```

回答を保存しただけではモデルは起動しません。piで`/human-resume`を実行すると、新しい入力を現在の分岐へ追加し、モデルの処理を開始します。新しい入力がなければ起動しません。常駐の自動再開は未実装です。

## セッションと分岐

依頼にはpiのセッションIDと、依頼を生成した会話上のエントリIDを対応付けます。そのエントリが現在の分岐に含まれている場合に、その依頼と結果を利用できます。共通の履歴を持つ分岐では、共通の依頼を参照できます。

結果反映時には、現在の分岐に既に記録されたイベントの依頼IDと順序番号を確認し、通常の操作で同じイベントを再追加しないようにします。別の分岐にその記録がなければ、該当する依頼の結果をその分岐へ反映できます。

結果を過去のツール結果へ書き換えて挿入せず、新しいカスタムメッセージとして提示します。古い版や取り消し後の回答は、現在の依頼の回答として反映しません。

## 現在の制限

- SQLiteとpiの履歴を一括で確定する仕組みはなく、モデル実行が厳密に一度だけになる保証はありません。
- 参加者IDは論理IDです。同じOSユーザーのプログラムによるDBの書き換えを防ぐ権限境界は設けていません。
- 依頼と入力の一覧はローカルの利用を対象とします。複数ユーザー向けの認証、外部への通知、Web UIは未実装です。
