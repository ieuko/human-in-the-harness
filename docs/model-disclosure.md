# モデルへの概念・情報の開示

モデルが、人間への接続をどんな構成要素として利用できるかを理解するための開示です。呼び出し口の存在に加え、利用方法、非同期の契約、参加者の申告情報、依頼の現在の状態を示します。

## 以前の実装

以前は、ツール名・入力スキーマ・短い説明と、受付と回答の違いやポーリングを避けるための注意書きを渡していました。人間の結果は、短い前置きと生のイベントJSONとして追加していました。

READMEや理論文書は、自動でモデルへ渡される仕組みではありませんでした。そのため、人間をシステムの構成要素としてどう使えるかを、モデルが十分に知る設計にはなっていませんでした。

## 現在の開示の段階

| 開示する場所 | 内容 |
|---|---|
| 実行開始時の概念説明 | 人間を含む知能システムという捉え方、利用できる機能の例、非同期の契約、結果の解釈 |
| ツールの説明・引数の説明 | 何を依頼できるか、何が返るか、目的・文脈・回答形式・締切の書き方 |
| `human_describe` | 利用候補の参加者、申告された能力、利用中のツール、接続の詳細、依頼状態 |
| 実行開始時の状態データ | 現在のセッション・分岐に属する依頼の要約と、参加者の説明 |
| ツール結果・到着イベント | 受付と結果の違い、状態の意味、入力の種類、出所、対象の依頼と版 |

役割やワークフローは固定しません。情報の想起、観察、調査、計画、評価、文脈の構成は利用例として説明します。

## モデルへ渡す概念説明

説明の原文は[src/model/disclosure.ts](../src/model/disclosure.ts)の`humanModelInstructions`です。例えば、次のように伝えます。

> Human-in-the-Harnessは、人間をモデルやソフトウェアとともに知能システムへ組み込む接続です。人間は必要に応じて、情報の想起・現場の観察・調査や計画・評価・次の推論に渡す文脈の構成などを担えます。これらは利用例であり、固定の役割や手順ではありません。

これに続けて、受付は回答の到着ではないこと、待機のためのポーリングを避けること、人間からの質問や辞退を扱うこと、能力や応答時間を保証しないことを説明します。

人間の結果はモデルの文脈へ届きます。この説明を追加したことで、人間の返答が次のモデル入力や実行規則を直接書き換えるようになったわけではありません。Human as Harnessの制御への接続は、別の設計対象です。

## 静的な契約と状態データを分ける

piの`before_agent_start`で、構造化されたシステムプロンプトの`human_in_the_harness`セクションへ静的な契約を追加します。他のセクションや、プロンプト全体を置き換えません。人間向けツールが無効な場合は、このセクションも提供しません。

参加者の説明、依頼の本文、人間の回答は、システム側の規則へ組み込まず、文脈上のデータとして渡します。参加者の能力は設定者による申告情報で、本人認証や能力の実測ではありません。応答可能性は`unknown`として示します。

完全なシステムプロンプトが強制指定されている場合、その文字列を変更せず、同じ説明を文脈メッセージ側に含めます。

## 状態の更新と圧縮

開始時の状態データは、現在の分岐に属する依頼の要約を最大20件含みます。取得範囲に上限がある場合は`mayHaveMore`で示します。最新の回答は`human_get`や到着イベントで確認します。

状態が変わっていなければ、同じスナップショットを毎回履歴へ追加しません。分岐や状態が変わった場合、または履歴の圧縮後には必要な状態を再提示します。別のセッションや、現在の分岐に属さない依頼は含めません。

## 人間の参加者の説明を設定する

piへの接続の`participants`オプションで、ID、説明、任意の能力の説明を設定できます。能力名を役割の列挙型や依頼の制約にはしません。省略時の宛先は先頭の参加者で、未設定なら`human`です。

実行できる設定例を[examples/pi/hith-extension.ts](../examples/pi/hith-extension.ts)に置いています。そこに記載する説明は例であり、実在する参加者の能力を示すものではありません。

```sh
npm run build
npx --no-install pi -e ./examples/pi/hith-extension.ts
```

## 開示内容を人間が確認する

piで`/human-context`を実行すると、この拡張が提供する概念説明と、参加者・依頼状態を表示します。モデル向けの`human_describe`でも、接続の詳細を取得できます。

この表示は本拡張が提供する情報です。ほかの拡張などが変更した後の、モデル入力全体を表示するものではありません。

## 検証することと、まだ主張しないこと

実際のpi SDKと、外部通信しないスクリプト化したモデルプロバイダーを使い、概念説明・状態・人間の入力がモデルへ渡る経路を確認します。分岐の分離、重複する状態の再注入、圧縮後の復元も確認します。

説明の追加によって、実モデルの依頼の作り方や判断が改善したかは未評価です。Human as Harnessとしての振る舞いを実現したという主張とも分けて扱います。
